## 1. 问题定义

湿实验研究（如移液、倍比稀释、取样）是由一长串**重复、精细**的操作组成的。这类工作里有两个反复出现的问题：

1. **错误发现太晚**。一个标错的管子或算错的稀释倍数，通常要到下游（几小时以后，甚至永远不会）才被发现。到那时再追溯"什么时候、为什么出错"几乎不可能。
2. **操作者的状态是"看不见"的**。人因研究表明，认知过载（脑子忙不过来）和注意力衰退是程序性操作的主要错误来源，但在真实实验室里，操作者的认知状态**从没被客观记录过**。现有办法只有两种：自我报告（不可靠，还会打断操作）和回看视频（准，但极度耗时——没人会重看两小时录像去抓那 5 秒的失误）。

缺的，是一个**低门槛、不打断操作**的记录工具：让操作者在干活时给事件（做完了哪步、发现了什么错）一键打标，事后能在**和生理状态信号（脑电）同一时间轴上**回看。这就把"我觉得我大概在一个多小时后哪步搞砸了"变成了可搜索、可回放的记录。

这个项目直接来自我在 AI4S³ 实验室（导师董航）的研究：我在一项进行中的"50 管材料分离"项目里负责每周三的取样与稀释模块。它背后真正的研究问题是"操作者状态与操作错误的关联"——这是我大一可行性研究的主题。**课程项目造工具，研究用工具。** 这是一个造工具的工程项目，不是人体实验研究。

## 2. 最终产品定义

**本课程的最终交付物是一个完整的桌面网页应用：LabPulse。**  
它在 Windows 笔记本上本地运行、通过浏览器使用——不用云服务、不用账号、不依赖网络，数据全部留在本机。提供一个一键启动脚本（`.bat`），不会编程的人也能打开就用。

成品包含**四大核心模块 + 四个扩展模块**：

**核心模块**

1. **导入与可信检查** —— 载入脑电文件（EDF/BDF/CSV），立刻显示信号质量面板（逐通道噪声底、平直通道标记、工频比值、尖峰计数），复用我已在设备验收中写好并验证过的分析内核。
2. **实时事件打标** —— 一键/热键事件按钮（"做完一步""发现错误"及自定义标签），打标带精确时间戳，不打断操作。
3. **同步回看** —— 操作时间线 × 脑电频段能量曲线（δ/θ/α/β 相对能量）在一张图上；点任意事件跳到它周围的大脑状态。
4. **结构化导出** —— 会话日志（事件 + 时间戳 + 质量标记）导出为 CSV，可直接进入分析。

**扩展模块**  
5\. **设备接入** —— 导入我自己 16 通道设备录的真实会话，通道名映射到标准 10–20 导联体系。  
6\. **实时模式** —— 数据经 LSL（或文件模拟实时）到达，时间线持续刷新，滚动显示 α/θ 指标。  
7\. **会话管理** —— 历史会话列表，可重新打开并补标/改标。  
8\. **体验打磨** —— 统一视觉、空状态提示、错误提示，以及演示脚本。

## 3. 目标用户与需求

**主用户**：做重复精细操作的科研工作者

| #  | 需求                      | 证据来源                                |
| -- | ----------------------- | ----------------------------------- |
| N1 | 干活时**一键打标**事件，不打断流程     | 我自己的稀释操作：双手都占着，任何需要打字的记录方式都不会发生     |
| N2 | 事后把"操作时间线"和"脑电状态曲线"并排回看 | 组会讨论（9/26）："先记录，后锁研究轴"——记录设施先于分析    |
| N3 | 立刻知道一段记录的信号质量是否可信       | 设备验收测试：任何脑电采集最先要做的就是信号质量检查          |
| N4 | 导出结构化会话日志供后续分析          | 研究计划要求把"会话结构日志"列为五项与研究问题无关的必备记录资产之一 |
| N5 | 事后能重新打开旧会话补标、改标         | 真实工作流：修正往往发生在会话结束后，而不是过程中           |

**次要用户**（仅用于验证）：无实验室背景的同学

### 6. 产品范围与 PRD 摘要

完整 PRD 见附件（`中文版_MVP_PRD.md`）。一段话概括：

LabPulse 是一个基于 Streamlit 的桌面网页应用（纯 Python），导入脑电记录、自动检查质量、干活时一键打标、把操作时间线与脑电频段能量曲线同步回放、导出结构化会话日志、管理历史会话，并在最终形态下经 LSL 接收我自己 16 通道设备的实时数据。其中信号质量模块**复用 `acceptance_check.py`**——我在设备验收阶段已写好并验证过的分析内核（对应课程目标"模块化与复用"）。公开脑电数据集（PhysioNet EEG 运动/想象数据集）作为演示基线，因此**核心产品永不依赖硬件是否到货或正常**；设备接入与实时模式属于扩展模块，各自有明确的降级路径。

## 7. 交付路径与风险控制

**范围声明**：这是一名大一学生在满课业之外（每周 4–6 小时）做的个人项目。野心在设计上就被限定：四个核心模块、一种语言、一个可复用的分析内核。**明确不做的**：自动认知状态分类（那是研究问题，不是课程交付物）、多用户账号、云端部署、手机 App。

**通往完整产品的路径**：

| 课程里程碑 | 日期 | 产品状态 | 受阻时的兜底 |
|---|---|---|---|
| 阶段二：MVP | 10/27 | 核心模块 1–4 基于公开数据集跑通 | 公开数据集本身就是基线 |
| 阶段三：用户验证 | 11/10 | 三层用户：我自己（真实周三会话）→ 实验室同学 → 3 名无背景同学；出修改计划 | 模拟会话方案 |
| 阶段四：Beta | 12/1 | + 模块 5（设备接入）+ 模块 7（会话管理） | 模拟实时模式顶上 |
| 阶段五：演示日 | 12/8 | **完整应用**：模块 1–8 齐全、界面打磨、现场演示 | 预录视频 + 公开数据现场跑 |

**扩展模块的风险控制**（核心四模块始终不受影响）：
- LSL 不稳 → 模拟实时模式替代，用户看到的体验一致
- 真实设备数据拿不到 → 用公开数据集 + 任何可用的设备记录
- 坏导插值建议 → 可直接砍掉，不影响其他模块
- 时间超支 → 模块 8（打磨）排最后；模块 5–7 各自独立可砍

## 8. 伦理、数据与 AI 合规

- **人的数据**：v1 只录我自己作为操作者（被试内可行性设计）；该记录的伦理审批已与导师确认无障碍。课程项目中不采集任何他人的生理数据。
- **隐私**：任何用于交叉核对的湿实验视频，若拍到人脸将先脱敏再使用；应用数据全部留在本地。
- **公开数据集**：PhysioNet EEG 运动/想象数据库（Schalk 等），按其开放许可使用并署名。
- **AI 使用**：AI 工具按课程 AI 合规规则作为实现助手使用；所有 AI 交互留档，AI 生成的代码在注释中标记，设计决策（问题定义、产品范围、指标）由我本人做出。任何敏感数据（未发表研究数据、凭据）不发送给外部 AI 工具。
